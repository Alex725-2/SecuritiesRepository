## Реальные PostgreSQL/RabbitMQ и CI

PostgreSQL необходим для проверок конкурентных Credit/Debit, встречных Transfer, одинаковых ключей, конкурентных Reverse, SQL rollback, CHECK/constraint triggers, больших и дробных decimal, повторного и прерванного DemoSeed. Эти тесты не заменены InMemory/SQLite или моками.

Пять отдельных transport-тестов используют настоящие RabbitMQ и PostgreSQL через Testcontainers: доставка, повтор, временная недоступность, восстановление, отсутствие маршрута. Проверяются порядок DeliveredAt после Inbox, единственный Inbox-эффект повторов и CompletedAt. No-route требует `MessageReturnedException`; TimeoutException не засчитывается как успех. Проверка недоступности подтверждает, что событие осталось недоставленным.

`.github/workflows/ci.yml` проверяет `docker info`, устанавливает **оба** флага, собирает и запускает тесты. Контейнеры PostgreSQL/RabbitMQ создаются самими тестами. Дополнительный шаг читает TRX и завершает CI ошибкой при отсутствии отчёта или любом непройденном/пропущенном интеграционном тесте. Ошибки запуска контейнеров не перехватываются как skip. Сам workflow в GitHub в этой сессии не выполнялся.

```powershell
$env:RUN_POSTGRES_TESTS='1'
$env:RUN_RABBITMQ_TESTS='1'
dotnet test -c Release
```

Без этих флагов пропуски видны в TRX. Итоговые отчёты текущего прогона находятся в `tests/*/TestResults/final_*.trx`; старые отчёты от предыдущих запусков не удалялись.

## Архитектура и первый Compose

Предметная область, границы проектов, PostgreSQL как источник истины и отдельный Worker сохранены. Уточнена доставка единственному потребителю: вместо publish в exchange используется send в именованную durable-очередь, а отметка DeliveredAt связана с сохранённым Inbox в общей БД. Это at-least-once с идемпотентным эффектом, без exactly-once delivery. Меняется публичный JSON-контракт decimal на строки; примеры README и Swagger обновлены.

Исходники, Dockerfiles и Compose подготовлены к первому запуску после заполнения deploy/.env. Успешный запуск **не подтверждён**: не выполнялись image build, Docker Compose, реальные PostgreSQL/RabbitMQ тесты и браузерный E2E. Поэтому эксплуатационная готовность пока не доказана. Пользовательские данные не удалялись; тесты используют отдельные временные контейнеры. CSV import и legacy migration не реализовывались.
