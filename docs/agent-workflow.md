# Контроль работы coding agent

Работа выполнялась в текущем репозитории без публикации и без установки SDK/Docker. Версия SDK закреплена global.json. Секреты передаются окружением; демонстрационный `.env.example` не содержит рабочих credentials.

Последовательность контроля:

1. Проверены SDK, Node, отсутствие Docker и пустой исходный каталог.
2. Созданы отдельные проекты с зависимостями на .NET 8 / EF Core 8.
3. Собрана модель и ядро; ошибки сборки исправлены до перехода к UI.
4. Чистые бизнес-правила вынесены в тестируемые функции. Проверка реальных гарантий PostgreSQL оставлена отдельным Testcontainers-набором.
5. Собраны API, Worker и React. SQL формируется непосредственно из EF модели, дополнительные ограничения централизованы в DatabaseSetup.
6. Выполнены доступные тесты и HTTP-проверки авторизации/Swagger. Недоступные контейнерные проверки перечислены отдельно.
7. CI повторяет сборку и тесты на Linux с Docker. Никаких автоматических публикаций образов, сайта, GitHub-репозитория или VPS нет.

Ограничение Windows sandbox: npm cache перенаправлен внутрь проекта. NuGet CLI не смог открыть HTTPS-источник; недостающие Testcontainers-пакеты загружены через Python HTTPS в локальный игнорируемый feed. SDK и другие тяжёлые инструменты не устанавливались. Системные кеши и файлы вне проекта не удалялись.

Временные генераторы не являются частью продукта; итоговый исходный код, документация, Dockerfiles, CI и инструмент форматирования Roslyn остаются доступными для ревью. Результат coding agent необходимо оценивать по сборке, инвариантам и реальным тестам, а не по размеру сгенерированного проекта.
